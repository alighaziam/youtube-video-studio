# Creator Workflow

This is the default workflow the product should make fast and repeatable.

## Suggested 5–8 minute software lesson
1. Hook (0:00–0:15): a problem or surprising engineering trade-off.
2. Context (0:15–0:45): why it matters.
3. Core idea (0:45–2:00): one clear concept.
4. Visual explanation (2:00–3:30): diagram or step-by-step flow.
5. Practical example (3:30–5:30): code, architecture, or decision scenario.
6. Trade-offs (5:30–6:30): when it works and when it does not.
7. Recap and CTA (final 20–30 seconds): key takeaway and next lesson.

The duration is editable; this is a starting template, not a fixed rule.

## Scene design rules
- One primary idea per scene.
- Prefer diagrams and short labels over paragraphs.
- Code scenes show only relevant lines and highlight the current line.
- Keep colors for roles and boundaries consistent throughout a lesson.
- Hold important diagrams long enough to read; avoid unnecessary transitions.
- Motion should explain sequence or causality, not decorate.
- No auto-zoom or camera movement on static scenes.
- Captions support the visual hierarchy; they do not replace it.

## Audio and captions
- Record voice-over in short scene-sized takes where practical.
- Keep original recordings; edits are non-destructive.
- Generate draft transcripts locally only when the user enables and installs a speech model.
- Correct technical terms, product names, acronyms, and punctuation manually.
- Export clean caption tracks separately from burned-in subtitles.

## Publishing pack
For each video, prepare three title candidates (search-led, curiosity-led, outcome-led), clear first two description lines, full description, actual scene-based chapters, relevant tags, thumbnail concept with one focal idea, and a cross-promotion caption for LinkedIn and Telegram.

Publishing remains manual. The studio never posts or uploads without explicit authorization.
